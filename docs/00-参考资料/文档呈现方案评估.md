## 方案对比

### 方案A: HTML单页文档（⭐ 推荐）

| 维度 | 评估 |
|------|------|
| **GitHub预览** | ✅ 原生支持 |
| **排版质量** | ✅ 完全可控 |
| **交互性** | ✅ 可添加折叠/标签页 |
| **维护成本** | 中 |
| **文件大小** | 小（可压缩） |

**适用场景：**
- 产品手册（多图片、复杂排版）
- 三折页（需要视觉冲击）

---

### 方案B: Base64内嵌图片的Markdown

| 维度 | 评估 |
|------|------|
| **GitHub预览** | ⚠️ 部分支持 |
| **排版质量** | ⚠️ 受限于Markdown语法 |
| **单文件** | ✅ 无需外部资源 |
| **文件体积** | ❌ 极大（可能50MB+） |
| **加载速度** | ❌ 很慢 |

**结论：** 不推荐，文件过大会导致GitHub加载超时

---

### 方案C: 保留PDF + 静态图片托管

| 维度 | 评估 |
|------|------|
| **GitHub预览** | ❌ 不支持 |
| **图片质量** | ✅ 原样保留 |
| **维护成本** | 高（需管理图床） |
| **访问速度** | 依赖图床服务 |

**结论：** 需要额外基础设施，不推荐

---

### 方案D: 高质量Markdown（无图片）

| 维度 | 评估 |
|------|------|
| **GitHub预览** | ✅ 完美支持 |
| **排版质量** | ⚠️ 无法展示图片内容 |
| **维护成本** | 低 |
| **文件大小** | 小 |

**结论：** 仅适用于以文本为主的文档（如已完成的通讯接口、感知开发指南）
