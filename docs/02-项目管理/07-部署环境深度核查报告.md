## 二、依赖包必要性评估

### 2.1 依赖使用统计

| 包名 | 使用文件数 | 是否必须 | 替代方案 |
|------|-----------|----------|----------|
| **loguru** | 13个源文件 | ⚠️ 可选 | 可用`logging`标准库替代 |
| **websockets** | 1个服务端文件 | ✅ 必须 | 可用`asyncio`手动实现 |
| **fastapi** | 1个服务端文件 | ✅ 必须 | 可用`http.server`替代（工作量大） |
| **uvicorn** | 1个服务端文件 | ✅ 必须 | 不可替代，需保留 |
| **pydantic** | 1个服务端文件 | ✅ 必须 | 可用`dataclasses`替代 |
| numpy | 全部感知模块 | ✅ 必须 | 不可减少 |
| cv2 | 感知模块 | ✅ 必须 | 不可减少 |
| requests | 网络请求 | ✅ 必须 | 可用`urllib`替代 |
| pyyaml | 配置解析 | ✅ 必须 | 可用`json`替代 |

### 2.2 最小化依赖方案分析

#### 方案A：保持现有依赖（推荐）

**优点**：
- 代码结构清晰，维护方便
- fastapi + uvicorn 提供完整的Web服务
- loguru 提供强大的日志功能

**缺点**：
- 需要5个额外依赖包
- 离线包约2.5MB

**适用场景**：所有场景

---

#### 方案B：移除loguru依赖

**修改范围**：
- 修改13个源文件的日志导入
- 将`from loguru import logger`改为`import logging; logger = logging.getLogger(__name__)`

**代码改动量**：中等（约13个文件）

**收益**：
- 减少一个依赖
- 使用标准库，无需额外安装

**适用场景**：需要进一步精简依赖时

---

#### 方案C：最小化依赖模式（不推荐）

**修改范围**：
- 移除loguru → 改用logging
- 移除fastapi/uvicorn/pydantic → 改用http.server
- 移除websockets → 改用asyncio手动实现

**代码改动量**：大量（影响monitor_platform/server.py核心逻辑）

**风险**：
- 代码复杂度增加
- 功能可能受限
- 维护成本上升

**适用场景**：极端资源受限环境

## 四、最终部署建议

### 4.1 推荐方案

**保持现有依赖结构，使用离线包部署**

理由：
1. 代码质量高，维护性好
2. 离线包体积小（~2.5MB）
3. 部署流程标准化
4. 符合竞赛规范要求

### 4.2 一键部署命令（已验证）

```bash
# 1. SSH登录
ssh ysc@192.168.1.103
# 密码: '

# 2. 从USB解压项目
cd ~
unzip -q /mnt/usb/lite3-power-inspection.zip
cd lite3-power-inspection

# 3. 创建虚拟环境
python3 -m venv venv && source venv/bin/activate

# 4. 安装依赖（使用离线包）
pip install --no-index --find-links=/mnt/usb/offline-deploy/packages -r requirements.txt

# 5. 验证安装
python3 -c "import loguru, websockets, fastapi, uvicorn, pydantic; print('✅ 全部依赖已安装')"

# 6. 启动演示
python3 scripts/demo_12min.py --mode simulation
```
