# 系统需求规格说明书

## 1. 引言

### 1.1 目的
本文档描述绝影Lite3电力场景巡检演示系统的功能需求和非功能需求，作为开发和测试的依据。

### 1.2 范围
本项目基于云深处绝影Lite3专业版机器狗，开发上装系统集成、数据采集与上报、视频流服务等模块，用于职业高校技能竞赛演示。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| Lite3 | 云深处绝影Lite3四足机器狗 |
| RTSP | Real Time Streaming Protocol，实时流传输协议 |
| WebSocket | 全双工通信协议，用于实时数据推送 |
| 上装系统 | 安装在机器狗上的附加设备和系统 |
| 沙盘 | 抽水蓄能电站缩小模型 |

---

## 2. 总体描述

### 2.1 产品视角
本系统是整个竞赛演示系统的核心组成部分，与以下系统交互：
- **监测平台**（第三方开发）：接收数据和视频流
- **沙盘模型**：提供演示环境
- **绝影Lite3本体**：提供运动控制和基础感知能力

### 2.2 用户特征

| 用户类型 | 特征 | 需求 |
|----------|------|------|
| 参赛选手 | 高校生，具备一定编程基础 | 易用、稳定、可演示 |
| 评委 | 行业专家 | 数据准确、功能完整 |
| 观众 | 非技术人员 | 视觉效果、演示流畅 |

### 2.3 假设与依赖
- 绝影Lite3专业版机器狗可用
- 沙盘的抽水蓄能电站模型已搭建
- 监测平台已就绪（或模拟）
- 现场网络环境稳定

## 3. 功能需求

### 3.1 FR-001: 机器狗状态监控

**描述**: 实时监控机器狗的运行状态，包括在线状态、电量、通信信号、运行模式。

**输入**: 机器狗内部传感器数据

**处理逻辑**:
1. 周期性读取机器狗状态（1Hz）
2. 格式化状态数据
3. 通过HTTP/WebSocket上报至监测平台

**输出**: 状态JSON数据

**状态字段定义**:
```json
{
  "device_id": "string",
  "online": "boolean",
  "battery_voltage": "float",
  "battery_percentage": "int",
  "signal_strength": "int",
  "signal_type": "string",
  "mode": "string",
  "timestamp": "datetime"
}
```

### 3.2 FR-002: 裂缝视觉检测

**描述**: 使用可见光相机检测混凝土表面的裂缝和蜂窝麻面。

**输入**: 可见光相机图像

**处理逻辑**:
1. 采集图像（分辨率≥1080p）
2. 运行裂缝检测算法
3. 过滤<0.1mm的裂缝
4. 计算裂缝宽度、长度、类型
5. 定位缺陷三维坐标
6. 上传检测数据和图像

**输出**: 裂缝检测数据 + 标记图像

**检测指标**:
- 最小识别裂缝宽度: 0.1mm
- 识别准确率: ≥90%
- 定位精度: ±5cm
- 处理延迟: <2秒/帧

### 3.3 FR-003: 温度监测

**描述**: 使用红外热像仪监测混凝土结构表面温度。

**输入**: 红外热成像图像

**处理逻辑**:
1. 采集热成像图像
2. 分析温度分布
3. 识别高温热点
4. 判断是否超过阈值（默认45℃）
5. 生成预警信号
6. 上传温度数据和热成像图像

**输出**: 温度数据 + 热成像图像 + 告警信号

**温度指标**:
- 测温范围: -20℃ ~ 150℃
- 测温精度: ±1℃
- 阈值: 45℃（可配置）
- 处理延迟: <1秒/帧

### 3.4 FR-004: RTSP视频流服务

**描述**: 提供RTSP视频流，供监测平台实时查看可见光和红外画面。

**视频流定义**:
| 流名称 | 类型 | 分辨率 | 帧率 | 编码 |
|--------|------|--------|------|------|
| visible | RTSP | 1920×1080 | 30fps | H.264 |
| thermal | RTSP | 640×512 | 9fps | H.264 |

**访问地址**:
- 可见光: `rtsp://<ip>:8554/visible`
- 红外: `rtsp://<ip>:8554/thermal`

### 3.5 FR-005: 巡检轨迹记录

**描述**: 记录机器狗巡检过程中的位置轨迹。

**输入**: 机器狗位置数据（IMU + 里程计）

**处理逻辑**:
1. 以10Hz频率记录位置
2. 格式化轨迹数据
3. 定期上传轨迹点

**输出**: 轨迹JSON数据

```json
{
  "trajectory": [
    {"x": 2.5, "y": 3.0, "z": 0.0, "timestamp": "2026-08-18T14:00:00Z"},
    ...
  ]
}
```

### 3.6 FR-006: 数据上报

**描述**: 通过HTTP API或WebSocket将数据上报至监测平台。

**上报内容**:
- 机器狗状态（FR-001）
- 裂缝检测结果（FR-002）
- 温度监测结果（FR-003）
- 巡检轨迹（FR-005）

**协议选项**:
| 协议 | 适用场景 | 特点 |
|------|----------|------|
| HTTP POST | 批量数据上报 | 简单、可靠 |
| WebSocket | 实时数据推送 | 低延迟、双向 |

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 视频流延迟 | <500ms |
| 数据上报延迟 | <1s |
| 裂缝检测延迟 | <2s/帧 |
| 温度测量延迟 | <1s/帧 |
| 系统启动时间 | <30s |

### 4.2 可靠性需求

| 指标 | 要求 |
|------|------|
| 演示成功率 | ≥95% |
| 数据不上报次数 | <3次/演示 |
| 视频流中断次数 | <2次/演示 |
| 平均无故障时间 | >2小时 |

### 4.3 可用性需求

| 指标 | 要求 |
|------|------|
| 操作学习成本 | <30分钟 |
| 故障恢复时间 | <5分钟 |
| 用户界面友好度 | 直观、简洁 |

### 4.4 安全性需求

- 数据加密传输（HTTPS/WSS）
- 设备认证机制
- 访问权限控制

## 5. 接口需求

### 5.1 硬件接口

| 接口 | 用途 | 数量 |
|------|------|------|
| USB 3.0 | 外接相机/热像仪 | 2 |
| Ethernet | 网络连接 | 1 |
| HDMI | 本地显示 | 1 |
| 24V电源 | 上装供电 | 1 |
| 5V/12V电源 | 传感器供电 | 各1 |

### 5.2 软件接口

| 接口 | 用途 |
|------|------|
| Lite3 Motion SDK | 运动控制 |
| Lite3 Perception SDK | 感知数据处理 |
| UDP通讯接口 | 与运动主机通信 |
| GStreamer | 视频流处理 |
| Flask/FastAPI | HTTP API服务 |
| WebSocket | 实时数据推送 |

### 5.3 外部系统接口

| 系统 | 接口 | 数据流向 |
|------|------|----------|
| 监测平台 | HTTP/WebSocket | 本项目 → 平台 |
| 监测平台 | RTSP | 本项目 → 平台 |

## 6. 约束条件

### 6.1 技术约束
- 必须基于绝影Lite3官方SDK开发
- 支持ROS1 (Melodic) 或 ROS2 (Humble)
- Python 3.8+ 开发语言
- Ubuntu 20.04 操作系统

### 6.2 时间约束
- 项目开发周期: 30天
- 演示时长: 12分钟
- 竞赛准备期: 10天

### 6.3 资源约束
- AI主机: Jetson Xavier NX (8GB)
- 内存限制: <6GB可用
- 存储空间: <10GB
